# Okulab Time

iPad と iPhone の 2 端末を使い、片方で **計測開始**、もう片方で **計測終了** を送信して、
その間の経過時間をミリ秒精度で記録・確認するための Web アプリです。

- **フロントエンド**: 静的 HTML / CSS / JavaScript(ビルド不要) → GitHub Pages
- **バックエンド**: Firebase Authentication(匿名)+ Cloud Firestore
- **Cloud Functions は使いません。** 経過時間の計算はブラウザ側で完結するため、
  Firebase は無料の **Spark プランのまま**運用できます。

## できること

- 2 台の端末が **同じ合言葉**を入力すると同じ「ルーム」に入り、状態がリアルタイムで同期されます。
- 端末ごとに役割(**計測開始** / **計測終了** / **閲覧のみ**)を選べます。入れ替えも自由です。
- 開始ボタン・終了ボタンを押した瞬間の時刻を **ミリ秒単位**で記録します。
- 開始から終了までの経過秒数を自動計算して保存します。
- 計測中は両方の端末に経過時間がリアルタイム表示されます。
- 記録一覧の閲覧、CSV 書き出し、削除、進行中の計測の中止ができます。
- 端末どうしの時計のズレを補正します(詳細は[時刻の精度について](#時刻の精度について))。
- 通信が一瞬切れた場合は、**押した時刻を保持したまま**自動で送り直します。

## 動作要件

- **iOS / iPadOS 16.4 以降の Safari** を推奨します。
  これより古い OS でも計測自体は動作しますが、一部の配色や選択中の強調表示が簡略化されます。
- **オフラインでは動作しません。** Service Worker を持たないため、
  ホーム画面に追加した場合でも、通信が無い状態ではアプリ自体が起動しません。
  実験中は Wi-Fi の接続状態を確認してください。

## セットアップ(Firebase)

所要時間はおよそ 10 分です。すべて無料枠(Spark プラン)の範囲で完結します。

### 1. Firebase プロジェクトを作成する

1. <https://console.firebase.google.com/> を開く
2. **プロジェクトを追加** をクリック
3. プロジェクト名を入力(例: `okulab-time`)
4. Google アナリティクスは **無効でかまいません**(有効にしても動作します)
5. 作成完了まで待つ

### 2. Firestore データベースを作成する

1. 左メニュー **構築 → Firestore Database**
2. **データベースの作成** をクリック
3. ロケーションは **`asia-northeast1`(東京)** を選択
   > 日本から使う場合、通信の往復が短くなり時刻の同期精度も上がります。
   > **ロケーションは後から変更できません。**
4. モードは **本番環境モードで開始**(ルールは次の手順で入れ替えます)
5. 作成完了まで待つ

### 3. セキュリティルールを設定する

1. Firestore Database の画面上部 **ルール** タブを開く
2. エディタの中身を **すべて削除**し、このリポジトリの
   [`firestore.rules`](firestore.rules) の中身を **そのまま貼り付ける**
3. **公開** をクリック

### 4. 匿名ログインを有効にする

1. 左メニュー **構築 → Authentication**
2. **始める** をクリック
3. **Sign-in method** タブ → プロバイダ一覧から **匿名** を選択
4. **有効にする** をオンにして **保存**

> 匿名ログインは、ユーザー登録なしで端末を識別するために使います。
> これを有効にしないとアプリは接続できません。

### 5. ウェブアプリを登録して設定値を取得する

1. 左メニューの歯車アイコン → **プロジェクトの設定**
2. **全般** タブを下にスクロールし、**マイアプリ** の **`</>`(ウェブ)** アイコンをクリック
3. アプリのニックネームを入力(例: `okulab-time-web`)
4. **「このアプリの Firebase Hosting も設定します」のチェックは不要**です
5. **アプリを登録** をクリック
6. 表示される `firebaseConfig` の中身をコピーする

```js
const firebaseConfig = {
  apiKey: "AIzaSy........",
  authDomain: "okulab-time.firebaseapp.com",
  projectId: "okulab-time",
  storageBucket: "okulab-time.firebasestorage.app",
  messagingSenderId: "1234567890",
  appId: "1:1234567890:web:abcdef......"
};
```

### 6. `js/firebase-config.js` を書き換える

このリポジトリの [`js/firebase-config.js`](js/firebase-config.js) を開き、
`YOUR_...` となっている値を手順 5 でコピーした値に置き換えて保存・コミットします。

> **`apiKey` は秘密鍵ではありません。** 公開されて問題ない識別子で、
> 実際のアクセス制御は手順 3 のセキュリティルールが担っています。
> そのままリポジトリにコミットして構いません。

### 7. 承認済みドメインに GitHub Pages を追加する ← **忘れやすい手順です**

1. **Authentication → Settings** タブ → **承認済みドメイン**
2. **ドメインを追加** をクリック
3. `choucrin.github.io` を追加して保存

> これを行わないと、GitHub Pages 上でログインに失敗します
> (`auth/unauthorized-domain` エラー)。

## セットアップ(GitHub Pages)

> **前提**: 無料アカウントで GitHub Pages を使う場合、リポジトリは
> **公開(public)** である必要があります。private のままだと 404 になります。
> `apiKey` は公開して差し支えない値なので、public で問題ありません。

1. GitHub でリポジトリ <https://github.com/choucrin/Okulab_time> を開く
2. **Settings** タブ → 左メニュー **Pages**
3. **Build and deployment** の **Source** を **Deploy from a branch** にする
4. **Branch** を **`main`** / フォルダを **`/ (root)`** にして **Save**
5. 1〜2 分待つと以下の URL で公開されます

```
https://choucrin.github.io/Okulab_time/
```

この URL を iPad と iPhone の Safari で開きます。
**ホーム画面に追加**(共有ボタン → ホーム画面に追加)しておくと、
アドレスバーのない全画面表示になり、実験中の誤タップを減らせます。

## 使い方

### 初回

1. 両方の端末で公開 URL を開く
2. **同じ合言葉**を入力する(例: `okulab-2026-visual`)
   - 合言葉は端末には保存されません。ハッシュ化した ID だけが保存されます
   - **大文字小文字・全角半角の違いは無視**されます
   - 入力欄の「表示」ボタンで、打ち間違いがないか目視確認できます
   - 合言葉が違うと別々のルームになり、相手の操作が見えません
3. それぞれの端末の役割を選ぶ
   - iPad → **計測開始**
   - iPhone → **計測終了**
4. **この端末を参加させる** をタップ

次回以降は自動的に同じルーム・同じ役割で開きます。
変更したいときは画面右上の **退出** をタップしてください。

### 計測

| 操作 | 端末 | 結果 |
|---|---|---|
| ラベルを入力(任意) | 開始担当 | 被験者名・条件名などを記録に残せます |
| **計測開始** をタップ | 開始担当 | その瞬間の時刻を記録。両端末が「計測中」に変わり、経過時間が動き出します |
| **計測終了** をタップ | 終了担当 | その瞬間の時刻と経過秒数を記録。両端末が「待機中」に戻ります |

- 計測中に再度「計測開始」を押すことはできません(ボタンが無効化されます)。
- 開始していない状態で「計測終了」を押すこともできません。
- 開始したまま終了し損ねた場合は **計測を中止** で破棄できます(記録は `aborted` として残ります)。
- 時刻同期がまだ完了していない状態でボタンを押すと、確認ダイアログが出ます。
  そのまま記録した場合は CSV の `start_synced` / `end_synced` が `false` になり、後から判別できます。

### 記録の確認・書き出し

画面下部の **記録** に新しい順で表示されます(一覧は**最新 300 件**まで)。
**CSV 書き出し** をタップすると、300 件を超えていても **すべての記録**を
取得し直して CSV ファイルとしてダウンロードします。

> ホーム画面に追加した状態(全画面表示)では、iOS の仕様上ダウンロードが
> うまく動かないことがあります。その場合は共有シートが開くので、
> 「ファイルに保存」を選んでください。うまくいかない場合は
> Safari で通常どおり URL を開いてから書き出してください。

## 記録されるデータ

Firestore 上の構造:

```
rooms/{roomId}/meta/current      … 進行中セッションの排他制御フラグ
rooms/{roomId}/sessions/{id}     … 1 回の計測 = 1 ドキュメント
rooms/{roomId}/clock/{uid}       … 時計同期用のプローブ置き場
```

`roomId` は合言葉の SHA-256(先頭 40 桁)です。合言葉そのものは送信も保存もされません。

1 件の計測ドキュメント:

| フィールド | CSV の列 | 内容 |
|---|---|---|
| `status` | `status` | `running` / `done` / `aborted` |
| `label` | `label` | 任意のラベル(最大 80 文字) |
| `startMs` | `start_ms` | 開始ボタンを押した時刻(補正後・ミリ秒) |
| `endMs` | `end_ms` | 終了ボタンを押した時刻(補正後・ミリ秒) |
| `durationMs` | `duration_ms` | `endMs - startMs`(ミリ秒) |
| `durationSec` | `duration_sec` | 同じ値を秒に換算したもの |
| `startRawMs` / `endRawMs` | `start_raw_ms` / `end_raw_ms` | 補正前の端末時計の値(検証用) |
| `startOffsetMs` / `endOffsetMs` | `start_offset_ms` / `end_offset_ms` | 適用した補正量 |
| `startAccuracyMs` / `endAccuracyMs` | `start_accuracy_ms` / `end_accuracy_ms` | 補正の推定誤差(± ミリ秒) |
| `startSynced` / `endSynced` | `start_synced` / `end_synced` | `false` なら未補正のまま記録された |
| `startedBy` / `endedBy` | `started_by` / `ended_by` | 操作した端末の匿名 ID |
| `startedAt` / `endedAt` | `server_started_at` / `server_ended_at` | サーバー側の受信時刻(参考値) |

CSV にはこのほか `session_id`、ローカル時刻表記(`start_local` / `end_local`)、
UTC 表記(`start_iso` / `end_iso`)も含まれます。

## 時刻の精度について

2 台の端末がそれぞれ自分の時計で時刻を読むと、**端末どうしの時計のズレが
そのまま計測誤差**になります(iOS の自動時刻設定でも数十〜数百ミリ秒ずれます)。

そこで本アプリは、Firestore のサーバー時刻を共通の基準時計として使い、
各端末が「サーバー時刻 − 自端末時刻」のオフセットを推定して補正します。

- 推定は SNTP と同じ方式です。書き込み直前と直後のローカル時刻で
  サーバーのタイムスタンプを挟み込み、往復が最も短かった試行を採用します。
- 往復時間の測定には、OS の時刻補正が走っても影響を受けない
  `performance.now()`(単調増加)を使っています。
- ルーム参加時に 5 回、以降 4 分ごと、および画面復帰・通信回復時に再測定します。
- 推定誤差は画面右上に **`同期 ±○ms`** として表示されます。
  Wi-Fi 環境では概ね ±50〜200ms 程度になります。
- 同期に失敗している間は **`同期失敗`** と表示し、画面に警告を出します。
- 補正前の生の値(`startRawMs` / `endRawMs`)も記録されるため、
  後から補正の妥当性を検証できます。

また、ボタンの押下時刻は `click` ではなく **`pointerdown`(指が触れた瞬間)** で
取得しています。指を離すまでの時間が誤差として乗らないようにするためです。
補正量や推定誤差も、押した瞬間の値をそのまま記録します。

> **外部キーボードなどで操作する場合**
> キーボードの Enter / Space で押した場合は `pointerdown` が発生しないため、
> わずかに遅い `click` の時刻が使われます。精度が必要な計測では画面をタップしてください。

> **より高い精度が必要な場合**
> ネットワーク経由の同期には原理的な限界があります。数ミリ秒以下の精度が必要な実験では、
> 1 台の端末で開始・終了の両方を操作するか、外部のハードウェアトリガーをご検討ください。

## セキュリティの考え方

想定しているのは「合言葉を共有した研究室内の端末どうしで使う」運用です。

`firestore.rules` が保証しているのは次の点です。

- 匿名ログインしていない端末は一切アクセスできない
- 合言葉(から導かれる `roomId`)を知らない限り、どのルームにも到達できない
  (Firestore はクライアントからのコレクション列挙ができないため)
- **記録された後**の開始時刻・ラベル・開始操作者は書き換えられない
- 終了操作で書き換えられるのは終了側の項目だけで、操作者 ID の詐称もできない
- 進行中の記録は削除できない
- 排他制御フラグ(`meta/current`)は決まった形以外では書き込めない

一方、**合言葉を知っている利用者が「もっともらしい偽の記録」を新規に作ること自体は
防げません**(正規の操作と区別がつかないため)。合言葉は推測されにくい文字列にしてください。

## コストの目安

Firebase の無料枠(Spark プラン)は 1 日あたり以下のとおりです。

| 項目 | 無料枠 / 日 |
|---|---|
| ドキュメント読み取り | 50,000 |
| ドキュメント書き込み | 20,000 |
| ドキュメント削除 | 20,000 |
| ストレージ | 1 GB |

本アプリの消費量:

| 操作 | 読み取り | 書き込み |
|---|---|---|
| 計測開始 1 回 | 1(トランザクション内) | 2 |
| 計測終了 1 回 | 2(トランザクション内) | 2 |
| 時計同期 1 プローブ | 1 | 1 |
| 画面を開く / 再接続 | 一覧の件数分(最大 300) | 0 |
| CSV 書き出し | 全記録の件数分 | 0 |

時計同期は参加時に 5 プローブ、以降 4 分ごとに 3 プローブです。
端末 1 台を 8 時間つなぎっぱなしにすると、時計同期だけで読み書き各 360 回程度、
2 台で 720 回程度になります。ここに計測回数分が加わります。

1 日に数百回計測し、何度もリロードしたとしても、
**無料枠を超えることはまずありません。** クレジットカードの登録も不要です。

## ローカルでの動作確認

`file://` で直接開くと、ES モジュールと Web Crypto API が使えないため動作しません。
簡易サーバーを立ててください。

```bash
python3 -m http.server 8000
```

その後 **<http://localhost:8000/>** を開きます。

> `python3 -m http.server` は起動時に `127.0.0.1` の URL を表示しますが、
> **`127.0.0.1` は Firebase の承認済みドメインに含まれていません。**
> かならず `localhost` の方で開いてください(`localhost` は最初から含まれています)。

同じ PC の 2 つのブラウザウィンドウ(片方をプライベートウィンドウ)で開けば、
2 端末の動作を再現できます。

> プライベートウィンドウでは認証状態が保持されないため、
> リロードのたびに別の匿名 ID になります(`started_by` の値が毎回変わります)。
> 動作確認では問題ありませんが、実際の実験では通常のウィンドウを使ってください。

## トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 「Firebase の設定が必要です」と表示される | `js/firebase-config.js` が `YOUR_...` のままです。手順 6 を行ってください |
| 「匿名ログインが無効です」と表示される | Authentication で匿名プロバイダを有効にしてください(手順 4) |
| 「このドメインは Firebase に許可されていません」と出る | 承認済みドメインに `choucrin.github.io` を追加してください(手順 7) |
| 「Firestore に拒否されました」と表示される | `firestore.rules` の内容が公開されているか確認してください(手順 3) |
| 相手の操作が反映されない | 両端末の合言葉が一致しているか確認してください。画面左上の `room ○○○○○○` が同じ値なら同じルームです |
| `同期失敗` と表示される | ネットワーク接続、または Firestore の作成状況・ルールを確認してください |
| 「進行中の記録を読み込めません」と出る | 状態がずれています。**計測を中止** を押すと待機中に戻せます |
| 経過秒数が負の値になる | 端末の時計が大きくずれています。iOS の 設定 → 一般 → 日付と時刻 で「自動設定」をオンにしてください |
| 経過秒数がオレンジ色で表示される | 時刻同期が完了しないまま記録されました。CSV の `start_synced` / `end_synced` で判別できます |
| CSV がダウンロードできない | ホーム画面に追加した全画面表示ではなく、Safari で URL を開いてから書き出してください |
| GitHub Pages が 404 になる | リポジトリが public か、Settings → Pages のブランチ設定を確認してください。公開まで 1〜2 分かかります |
| ページが真っ白のまま進まない | 通信が無い状態では起動できません(オフライン非対応)。接続を確認してください |
